# Mode A:面试前调研(详细执行流程)

> **触发**:用户说「面试 X 公司」「准备 X 面试」「X 公司打电话」「调研一下 X」「Boss 直聘约面试」等。

## 前置准备(必做)

执行任何步骤前,先读取 [`../config.md`](../config.md) 拿到 `sessions_dir` / 身份 / 飞书配置,再读取 [`../profile/profile.md`](../profile/profile.md)、[`../profile/projects.md`](../profile/projects.md)、[`../profile/talking-points.md`](../profile/talking-points.md)、[`../profile/qa-bank.md`](../profile/qa-bank.md)。

> 若 profile 文件里仍有大量 `<尖括号>` 占位符,说明用户没填资料 —— 先提醒去填 `config.md` + `profile/`,或主动引导逐项补全,不要拿空模板硬生成。

## 信息收集阶段(对话式补全)

### Step 1:确认必要输入

如果用户提供的信息不完整,**最多问 1 轮(2-3 个问题合并)** 获取以下信息:

| 必需 | 信息项 | 用途 |
|-|-|-|
| ✅ | 公司名 | 文件夹命名 + 公司画像查询 |
| ✅ | 岗位名 | JD 拆解 |
| ✅ | JD 文本或截图 | 关键词提取、匹配点分析 |
| 🟡 | 薪资范围 | 谈薪策略 |
| 🟡 | 当前面试轮次(R1/R2/R3/R4) | Q&A 侧重点 |
| 🟡 | 已有的 HR 微信/电话沟通记录 | 排除已问过的问题 |
| 🟡 | 面试官姓名/title(若知) | 反查背景 |

### Step 2:创建会话目录

```bash
mkdir -p "<sessions_dir>/<公司名>"   # sessions_dir 取自 config.md
```

### Step 3:写入基础信息文件

创建 `00-基础信息.md`:
```
# <公司名> 面试基础信息

- **岗位**:<岗位名>
- **薪资范围**:<薪资>
- **来源**:Boss 直聘 / 内推 / 猎头 / 其他
- **HR 姓名**:<若知>
- **面试官**:<若知 + title>
- **当前轮次**:R<1/2/3/4>
- **面试时间**:<日期 时间 / 待定>
- **面试形式**:电话 / 视频 / 现场
- **链路**:R1(已完成/待) → R2(已完成/待) → R3 → R4
- **创建时间**:<YYYY-MM-DD>
```

## 调研执行阶段(并行 5 个动作)

### Action 1:公司画像调研 → `01-公司画像.md`

**步骤**:
1. 用 WebSearch 查公司基本信息(全称、总部、成立时间、CEO 背景、员工规模、融资情况)
2. 用 WebSearch 查主营业务、产品线、近期动态(2024-2025)
3. 用 WebSearch 查与岗位强相关的布局(核心业务/技术/产品线,以及该岗位所在条线的具体产品名)
4. 用 WebSearch 查潜在负面信号(裁员、996 投诉、业务收缩、IPO 失败等)
5. 综合判断这家公司和用户(见 profile.md)的 3 个最强对接点

**输出模板**:见 [`../templates/company-profile.md`](../templates/company-profile.md)

### Action 2:JD 拆解与匹配点 → `02-JD拆解与匹配点.md`

**步骤**:
1. 把 JD 拆成 5-8 个核心能力关键词(从 JD 原文里提炼,如「XX 管理」「XX 系统」「XX 增长」等)
2. 每个关键词对应到用户的真实经历(从 `profile/projects.md` 取例)
3. 标注「强匹配 / 中等匹配 / 弱匹配 / 待补」4 档
4. 对每个「弱匹配 / 待补」给"如果被问到怎么答"的话术

**输出模板**:见 [`../templates/jd-mapping.md`](../templates/jd-mapping.md)

### Action 3:Q&A 预测(分轮次) → `03-Q&A预测.md`

**Q&A 题量规则**(按当前面试轮次):
- R1 HR 初筛:**10-15 题**(开场 + 离职 + 薪资 + 稳定性 + 项目浅问)
- R2 业务面:**12-18 题**(项目深问 + case study + 技术细节 + 行业判断)
- R3 CEO/VP 面:**6-10 题**(长期动机 + 行业判断 + 文化匹配 + 战略视角)
- R4 终面/HRBP:**5-8 题**(谈薪 + 入职时间 + 背调 + Offer 细节)

**每题格式**(严格遵守):
```
### Q[轮次]-[序号] 问题

**HR 意图**:[一句话说明对方为什么问]

**你的答案**:[基于 profile/projects.md 的真实数据,80-200 字]

**⚠️ 雷区**:[不要怎么答,1-2 条]

**加分点**(可选):[如果答出某点会加分]
```

**Q&A 题目来源**:
1. 优先从 [`../profile/qa-bank.md`](../profile/qa-bank.md) 抽相关题(已有标准答案)
2. 根据公司画像和 JD 的特殊性追加 5-10 道定制题
3. 必须覆盖 4 大类:**开场/离职(2-3)、岗位匹配(4-6)、项目深度(3-5)、稳定性/性格(2-3)**
4. R2 及以上额外覆盖**行业判断 + 专业/技术深度**

### Action 4:反问板块 → `04-反问板块.md`

**反问规则**:
- 每轮反问 3-5 个,标注「必问」「加分项」
- R1 关注:岗位归属 / 团队规模 / 招聘节奏
- R2 关注:产品挑战 / 技术栈 / 决策机制
- R3 关注:战略目标 / 业务定位 / 理想 PM 画像
- R4 关注:薪资构成 / 期权细节 / 试用期标准

**模板**:见 [`../profile/talking-points.md`](../profile/talking-points.md) 的"反问问题库"

### Action 5:话术速查卡 → `05-话术速查.md`

**结构**:
1. **60 秒自我介绍**(套用 `talking-points.md` 标准版 + 替换公司名为目标公司)
2. **离职原因**(从用户准备的若干版中挑出最适合这家公司的版本,说明选择理由)
3. **期望薪资**(基于该公司薪资范围 + 用户预期,生成具体话术)
4. **弱项话术**(根据 JD 选 1 个最弱项 + 补救方案)
5. **差异化信号**(从 profile.md 取,根据 JD 排序,标注哪 2 个必塞)

## 临场提醒 / 注意事项

输出最后追加一段「⚠️ 临场必读 5 条」:
1. 语速放慢 20%
2. 关键词主动念出来:[从 JD + profile 提炼出的 3-5 个本岗位核心术语]、[公司具体产品名]
3. 遇到不会的:"这块没直接做过,但做过 X,可以快速补"
4. 结尾主动:"如果方便,我希望尽快安排下一轮"
5. 不报死数字、不暴负面、不卑不亢

## Action 6:同步到飞书知识库(仅当 config 开启)

**仅当 `config.md` 里 `lark_enabled=true` 时执行**:按 [`lark-sync.md`](lark-sync.md) 执行同步,把 01-05 五个文件合并成一段 markdown 创建飞书文档。

**跳过条件**:`lark_enabled=false`,或用户明确说"不要同步飞书" / "skip 飞书" / "只本地"。

同步失败**不阻塞**主流程,但要在最终汇报里告知用户失败原因。

## 增量更新场景

如果用户说「准备 X 公司的 R2 面试,根据我跟 HR 的 R1 录音」:
1. 检查 `sessions/<公司名>/06-面试实录Q&A.md` 是否存在
2. 读取已沉淀的 HR 透露信息(团队规模 / 业务挑战 / 招聘动机等)
3. **只更新** `03-Q&A预测.md` 的 R2 章节和 `04-反问板块.md` 的 R2 章节
4. **不覆盖** `01-公司画像.md`(已查的不再查)
