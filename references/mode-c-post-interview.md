# Mode C:面试后录音复盘

> **触发**:用户说「复盘这次面试」「整理录音」「这是录音转文字稿」并粘贴/上传文字稿等。

## 前置准备

执行任何步骤前,读取 [`../config.md`](../config.md)(拿 `sessions_dir` / 飞书配置)+ [`../profile/profile.md`](../profile/profile.md) + [`../profile/qa-bank.md`](../profile/qa-bank.md)。

## Step 1:确认基础信息

如果用户只发了文字稿,**1 次性问清**:
- 这是哪家公司?哪一轮(R1/R2/R3/R4)?
- 面试官身份(HR / 业务 / CEO)?
- 面试时长?
- 你自己感觉:很好 / 一般 / 不好?

(如果用户已在 `<sessions_dir>/` 里有对应公司目录,直接读 00-基础信息.md 拿这些信息)

## Step 2:文字稿预处理

> ⚠️ 长录音 / 密集追问时最常见的两个事故:① 把连续追问折叠进上一题的 `###` 子标题,导致题号跳号、整段问答被吞;② 把第一人称回答压成「你答:…」概括或省略号截断。Step 2/2.5/3/3.5 的所有约束都是为了**杜绝"漏整段 + 答案截断"**。触发它的不是录音长,而是**密集追问**(连续 ≥4 问)。

### Step 2.0:原始文字稿落盘(最先做,不可跳过)

做任何清洗 / 提取之前,**先把用户粘贴或上传的原始文字稿原封不动写入 `<sessions_dir>/<公司名>/_raw-transcript.md`**(一字不改、不清洗、不删口语词)。

- 这是后续覆盖率自检(Step 3.5)和漏题回溯的**唯一对照源**,必须先于一切处理执行。
- 首行写注释:`<!-- 原始文字稿,只读对照源,请勿编辑;清洗版见 06-面试实录Q&A.md -->`
- 若已存在(二次补稿),不覆盖,改存 `_raw-transcript-2.md`,Step 3.5 合并计数。

### Step 2.1:清洗与说话人标注

录音转文字稿通常有这些问题:错别字(专有名词、行业术语易识别错)、说话人混淆、口语化("呃""那个""就是说")、顺序错乱(重叠对话)。

**预处理动作**(在生成 Q&A 前,且必须在原稿已落盘之后):
1. 通读全文,**逐段标记说话人是「面试官」还是「用户本人」**(多面试官场景标到具体角色:HR / 业务 / leader / CEO 等)
2. **穷举提取每一个面试官的提问 —— 不做任何「关键 / 不关键」的主观筛选**。凡是面试官说出的、需要用户回答的话,无论是正式问题、追问("那你觉得呢""接着说""为什么")、反问、还是看似随口的一句,**全部算一题**。宁可多列也不许合并、不许判定某个追问"不重要"而吞掉。
3. 修正明显的语音识别错误(对照 profile 里的专业术语)

### Step 2.5:强制穷举编号(覆盖率锚点,静默执行)

把上一步穷举到的所有面试官提问,**按文字稿出现顺序逐一编号**,写入 `<sessions_dir>/<公司名>/_question-list.md`,作为 Step 3 必须 1:1 落地、Step 3.5 必须对账的硬基线。

**编号体系(铁律,全篇统一,不要发明多套格式):**
- 统一用 **`Q[轮次]-实录[全局序号]`** 双层编号。轮次号标识 R1/R2 哪一轮;**全局序号在整篇内从 1 连续递增、绝不跳号、绝不重号**。
- **追问也独立占一个全局序号**,但**继承上一题的轮次号**——这样既"不漏"(每个追问独立成行),又"重点突出"(同一深挖回合靠相同轮次号天然聚类)。例:`Q2-实录5` / `Q2-实录6` / `Q2-实录7` 是对 Q2 话题的连环追问。
- 覆盖率/连续性**只校验全局序号 1..N 连续**;轮次号允许重复。
- 一行只写一题,**严禁两个提问挤在同一行**。

**`_question-list.md` 格式**(每题只写编号 + 一句话 + 原稿位置,不展开答案,目的是锁定总题数 N):
```
本场共穷举出 N 道题(含追问)。全局序号 1..N。
- 实录1  [R1] [问题一句话]            (原稿 ~第X段)
- 实录2  [R1] [问题一句话]            (原稿 ~第X段)
- 实录3  [R1] [追问:问题一句话]       (原稿 ~第X段)
- ...
- 实录N  [RX] [问题一句话]            (原稿 ~第X段)
```

**默认静默,不打断用户**:清单照常落盘并作为内部对照基线使用,**不主动弹给用户核对**。仅当 Step 3.5 自检出现 ❌ 时,才把清单连同自检报告一起回弹给用户。

## Step 3:生成实录 Q&A → `06-面试实录Q&A.md`

**⚠ 结构铁律(违反任何一条都算输出失败,必须重做):**

1. **一题 = 一个独立的 `## Q[轮次]-实录[全局序号]` 二级标题**。Step 2.5 清单里有几题,这里就有几个 `##`,**一一对应、数量必须相等**。
2. **严禁把后续问题 / 追问写成上一题内部的 `###` 子标题**。`###` 只能用于一道题内部的固定五段模板;**绝不允许出现 `### 接着问` `### 又问` `### Q12` `### 第二个问题` 这种把新问题塞进旧题的写法**,也不许把新问题塞进上一题的 `> blockquote` 里。
3. **连环追问各自独立成题**,标题继承上一题轮次号、全局序号顺延(如 `## Q2-实录5` → `## Q2-实录6`),与 Step 2.5 清单严格一致。
4. **全局序号连续、绝不跳号**:实录1、实录2 … 实录N 一个不少。写完发现实录9 下面直接跳到实录11,说明实录10 被吞了,必须回 Step 2.5 清单补出来。
5. **每一道题都必须套满下面五段模板,一段不能省**(包括追问题也要五段齐全,严禁只给一句话概括)。

**每题格式**(五段齐全,顺序固定,段名必须逐字照抄、不许换近义词):
```
## Q[轮次]-实录[全局序号] [问题]

### 面试官原话
> [逐字摘录面试官原话,只许修标点和明显错别字,不许概括]

### 你的回答(实录)
> [逐字摘录用户本人的第一人称原话,必须用 > blockquote 整段引用。
>  铁律:① 必须第一人称原话,严禁写成第三人称「你答:…」「他/她说…」或编辑式概括(背景/痛点 bullet);
>        ② 严禁用省略号「…」把长句砍断截留半句;长就长,完整搬过来;
>        ③ 只允许删掉纯填充词(呃 / 那个 / 就是说),其余一字不改、不改写、不归纳。]

### 我的评分
[1-5 分] | [优点 1 句] | [不足 1 句]

### 更优回答
[基于 profile/projects.md 用户真实数据,带数据、带结论、80-200 字。段名固定为「更优回答」,不许换近义标题]

### 关键改进点
- [1-3 条具体改进建议,如"主动报数据"、"避免使用'就是说'"。段名固定为「关键改进点」,不许换近义标题]
```

**长稿 / 密集追问处理(避免一次性生成触发折叠省力):**

触发条件**只看追问密度,不看行数**:若某处出现**连续 ≥4 问的密集追问回合**,不要一次性整篇生成 06,改为:
1. 按面试自然段(开场 / 项目深挖 / 追问回合 / 收尾)**分块逐题产出**;
2. 每块末尾打印「本块已覆盖 实录_ 到 实录_,累计 X 题」,下一块从 X+1 续号;
3. 密集追问回合**必须逐问拆开**,绝不因为"都在追同一件事"就压成一题;
4. 全部块产出完毕后,统一进 Step 3.5 对账。

**评分标准**:
- 5 分:答案有结构、有数据、有匹配,展现该岗位的高密度专业信号
- 4 分:答案完整但偏平淡,缺关键数据或案例
- 3 分:答案能听懂但不够亮眼,常规水平
- 2 分:有明显漏洞 / 表达不清 / 答非所问
- 1 分:暴露明显弱点 / 错误 / 不自信

## Step 3.5:输出后自检门(脚本机械校验,必须通过才能进 Step 4)

生成完 `06-面试实录Q&A.md` 后,**先别急着写薄弱点诊断**。这一步**不靠模型自省**(刚把题折叠掉的模型,自检时往往看不见自己的盲区),而是**跑脚本机械校验**:

```bash
python3 <skill_dir>/scripts/qa-lint.py \
  "<sessions_dir>/<公司名>/06-面试实录Q&A.md" \
  "<sessions_dir>/<公司名>/_raw-transcript.md"
```

> `<skill_dir>` 是本 skill 的根目录(含 `references/`、`scripts/` 的那一层)。

脚本做三件机械可验证的事(实现见 [`../scripts/qa-lint.py`](../scripts/qa-lint.py)):
- **(a) 题号连续性**:抽出所有 `## Q[轮]-实录[全局序]`,断言全局序号集合 == `1..N` 连续、无缺、无重。出现 Q10→Q14 跳号立即红。
- **(b) 五段模板完整性**:每个 `## Q` 块的核心三段(`### 面试官原话` / `### 你的回答(实录)` / `### 我的评分`)必有;低分题(评分≤3)还须有 `### 更优回答` + `### 关键改进点`。段名逐字匹配(允许「更优回答(补充说明)」这类带括号后缀);近义替身(怎么修正 / 唯一遗憾)算缺段。
- **(c) 保真度 + 覆盖率**:① grep `你答` / `你回答说` / 省略号截断模式(揪出第三人称概括);② 数 `_raw-transcript.md` 里**「面试官」发言的轮次数**(不是数问号——追问"那你觉得呢"很多没问号),与 06 题数 N 比对,题数明显少于面试官发言轮次 = 一定有合并漏题。

**放行规则**:把脚本 stdout 原样贴出。三项全 ✅ 才能进 Step 4;任一 ❌,**回 `_raw-transcript.md` 取原话补齐 / 拆题 / 去概括,再重跑脚本**,直到全绿。出现 ❌ 时把 `_question-list.md` 连同报告一起回弹给用户。

## Step 6:回写 qa-bank.md

将本场面试中**新出现的高频问题**自动追加到 [`../profile/qa-bank.md`](../profile/qa-bank.md) 的「第八章:补充 Q&A」末尾。

格式严格按 qa-bank.md 中的规范:
```
### Q[公司缩写]-[序号] [问题]
**场景**:[公司 R几]
**当时回答**:[摘录关键句]
**更优回答**:[完整改进版]
**关键改进点**:[一句话]
```

**注意**:不是所有问题都加,只加这两类:
1. **跨公司可能复现的高频问题**(如"你怎么看 <你所在行业> 未来 2 年的发展")
2. **用户答得不好、需要标准化改进的问题**

格式严格遵守:
