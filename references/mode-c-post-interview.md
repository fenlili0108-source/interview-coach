# Mode C:面试后录音复盘

> **触发**:用户说「复盘这次面试」「整理录音」「这是录音转文字稿」并粘贴/上传文字稿等。

## 前置准备

执行任何步骤前,读取 [`../config.md`](../config.md)(拿 `sessions_dir` / 飞书配置)+ [`../profile/profile.md`](../profile/profile.md) + [`../profile/qa-bank.md`](../profile/qa-bank.md)。

## Step 1:确认基础信息

如果用户只发了文字稿,**1 次性问清**:
- 这是哪家公司?哪一轮(R1/R2/R3/R4)?
- 面试官身份(HR / 业务 / CEO)?
- 面试时长?
- 你自己感觉:很好 / 一般 / 不好?

(如果用户已在 `<sessions_dir>/` 里有对应公司目录,直接读 00-基础信息.md 拿这些信息)

## Step 2:文字稿预处理

录音转文字稿通常有这些问题:
- ❌ 错别字(尤其专有名词、行业术语容易被识别错)
- ❌ 说话人混淆(没标 面试官 / 你)
- ❌ 口语化("呃"、"那个"、"就是说")
- ❌ 顺序错乱(尤其重叠对话)

**预处理动作**(在生成 Q&A 前):
1. 通读全文,标记每段是「面试官」还是「用户本人」
2. 提取关键问题(通常是疑问句 + 反问句)
3. 修正明显的语音识别错误(对照 profile 里的专业术语)
4. 输出"清洗后的对话提纲"(给用户确认前可以省略,直接进 Step 3)

## Step 3:生成实录 Q&A → `06-面试实录Q&A.md`

**每题格式**:
```
## Q[轮次]-实录[序号] [问题]

### 面试官原话
> [尽量还原,标点修正]

### 你的回答(实录)
> [从文字稿提取,口语词保留]

### 我的评分
[1-5 分] | [优点 1 句] | [不足 1 句]

### 更优回答(改写版)
[基于 profile/projects.md 用户真实数据,带数据、带结论、80-200 字]

### 关键改进点
- [1-3 条具体改进建议,如"主动报数据"、"避免使用'就是说'"]
```

**评分标准**:
- 5 分:答案有结构、有数据、有匹配,展现该岗位的高密度专业信号
- 4 分:答案完整但偏平淡,缺关键数据或案例
- 3 分:答案能听懂但不够亮眼,常规水平
- 2 分:有明显漏洞 / 表达不清 / 答非所问
- 1 分:暴露明显弱点 / 错误 / 不自信

## Step 6:回写 qa-bank.md

将本场面试中**新出现的高频问题**自动追加到 [`../profile/qa-bank.md`](../profile/qa-bank.md) 的「第八章:补充 Q&A」末尾。

格式严格按 qa-bank.md 中的规范:
```
### Q[公司缩写]-[序号] [问题]
**场景**:[公司 R几]
**当时回答**:[摘录关键句]
**更优回答**:[完整改进版]
**关键改进点**:[一句话]
```

**注意**:不是所有问题都加,只加这两类:
1. **跨公司可能复现的高频问题**(如"你怎么看 <你所在行业> 未来 2 年的发展")
2. **用户答得不好、需要标准化改进的问题**

## Step 7:同步到飞书知识库(仅当 config 开启)

**仅当 `config.md` 里 `lark_enabled=true` 时执行**:按 [`lark-sync.md`](lark-sync.md) 的「Mode C 后的同步流程」执行,把 06-08 三个文件作为新的复盘 section **追加**到该公司已有的飞书文档末尾。

格式严格遵守:
```markdown
---

# 📋 R<X> 面试复盘 · <YYYY-MM-DD>

## 一、实录 Q&A
[06 内容]

## 二、薄弱点与改进
[07 内容]

## 三、后续行动
[08 内容]
```

**跳过条件**:`lark_enabled=false`,或用户明确说"不要同步飞书"。同步失败不阻塞主流程。
